# GitHub Projects для bb

Рабочее пространство GitHub Projects: несколько проектов, «Мои задачи», сгруппированный список и доска. GitHub остаётся источником проектов, статусов, полей и обсуждений. Установка или сборка плагина сама по себе не подтверждает доступ к GitHub или успешную запись.

## Язык интерфейса

По умолчанию интерфейс на английском. В Settings → Language можно сразу переключить его на русский (Русский) или обратно на English; сохранять подключение заново не требуется. Язык хранится отдельно в этом браузере, восстанавливается после перезапуска и синхронизируется между открытыми вкладками. Даты, время (24 часа) и числительные следуют выбранному языку. Названия проектов, статусов и полей GitHub, задачи и комментарии не переводятся. Диагностика самого GitHub/gh, для которой нет перевода в плагине, сохраняется в исходном виде. Служебные настройки, которые рисует сам bb вне рабочего пространства плагина, имеют английские подписи.

MVP не требует отдельной библиотеки: React-контекст в `src/ui/i18n.tsx`, каталоги English/Russian в `src/i18n/`, форматирование через Intl. Русские исходные фразы служат стабильными ключами, параметры предложений передаются отдельно. Для новой строки добавьте английский перевод в соответствующий каталог и используйте `t()`; не передавайте пользовательский текст в переводчик.

## Подключение

Нужны bb ≥0.48, GitHub CLI `gh` на машине сервера и доступ к нужным проектам. Плагин использует **общую серверную сессию gh**: это не персональная OAuth-авторизация каждого участника. Авторство и права всех изменений соответствуют этому GitHub-аккаунту.

Для чтения нужен scope `read:project`; для редактирования — `project`. Репозиторий также должен быть доступен аккаунту; для приватных репозиториев могут потребоваться соответствующие права и разрешение SSO организации. Расширить OAuth-сессию gh:

```sh
gh auth refresh --hostname github.com --scopes project
```

Переменные окружения сервера `GH_TOKEN` / `GITHUB_TOKEN` имеют приоритет над сохранённой сессией gh. Плагин не создаёт собственного хранилища токенов. Необязательная настройка `tokenFile` указывает на файл токена **на сервере**; его содержимое не передаётся интерфейсу. Ограничьте доступ к этому файлу учётной записью сервера.

Откройте **Projects → Настройки**, введите пользователя или организацию, найдите проекты и выберите до 25. Можно искать нескольких владельцев, сохраняя выбранные проекты. Репозиторий по умолчанию необязателен. Подключённые проекты показаны по названиям; отключение проекта вступает в силу только после сохранения настроек. Текущий GitHub-аккаунт указан в настройках.

## Работа

- Обзор показывает реальные количества задач по статусам; нажатие на статус открывает соответствующий список. «Мои задачи» использует login серверного gh.
- В проекте доступны поиск, фильтры исполнителя и статуса, сортировка, список и доска. Группы берутся из поля статуса проекта. Можно выбрать реальное поле даты для показа в списке.
- На компьютере задачи можно перетаскивать между колонками доски: это изменяет поле статуса в GitHub. Карточка перемещается сразу и остаётся на месте при фоновом чтении; при ошибке откатывается только изменение статуса.
- В карточке доступны идентификатор и копирование, переход в GitHub, изменение названия, описания, исполнителей, полей single-select и даты. Запись выполняется явной кнопкой сохранения. Поддерживаются существующие поля Single select, Text, Number и Date: редактирование, очистка и заполнение при создании задачи. Итерации, multi-select и связанные встроенные поля этим редактором не изменяются.
- Обсуждение задачи доступно из списка и доски; количество комментариев видно на карточках. Комментарии загружаются постранично и отображаются через Markdown-компонент SDK bb. Редактор поддерживает форматирование, предпросмотр и подсказки @упоминаний с именем и login. Ответ добавляет цитату, ссылку на исходный комментарий и @упоминание в обычный комментарий; это не отдельная ветка GitHub. Публикация выполняется явной кнопкой. Связанные pull request показываются, когда они доступны через API.
- Новая задача без репозитория становится черновиком Projects; у черновика нет комментариев. С репозиторием создаётся issue, затем добавляется в проект. Эти шаги не атомарны: при частичном результате интерфейс показывает предупреждение и ссылку. Перед повторной отправкой проверьте GitHub, чтобы не создать дубликат.

Локально сохраняются последний раздел/проект, список или доска, поиск, фильтры, сортировка, поля даты, открытая задача и прокрутка списка/доски. Они восстанавливаются после повторного открытия и перезагрузки приложения; явная ссылка на задачу имеет приоритет. Несохранённые комментарии, черновики редактирования задач и учётные данные в это состояние не входят. Оформление следует теме bb. Дополнительных локальных политик обязательных полей или ролевых режимов нет. Проверка агентом и приёмка человеком не выдумываются: отображаются только существующие поля GitHub.

Колонки доски можно переставлять за заголовок; с клавиатуры — Alt + стрелка влево/вправо на заголовке. Кнопка со стрелкой сворачивает колонку в узкую вертикальную полосу. Свёрнутую колонку также можно переставлять и использовать как цель переноса задач. Порядок и свёрнутое состояние сохраняются отдельно для каждого раздела/проекта в этом браузере; порядок статусов в GitHub не меняется. По умолчанию колонка Without status / «Без статуса» идёт последней. Ранее сохранённый пользователем порядок имеет приоритет.

## Пользовательские поля

Плагин читает поля из самого проекта GitHub. Например, в Workroom доступны Priority и Area: они видны на карточках списка и доски, редактируются в задаче и заполняются при создании новой. Раздел Card fields позволяет выбрать поля на карточках; значения фильтруются над списком/доской. Фильтры и видимость сохраняются локально для каждого проекта. Приоритет выбирается кнопками без выпадающего списка: можно включить несколько вариантов, включая пустое значение; внутри одного поля действует «или», между полями — «и». Названия и варианты кнопок берутся из GitHub. Весь блок фильтров сворачивается кнопкой Filters; число активных критериев и сброс доступны в свёрнутом виде. Открытое/свёрнутое состояние сохраняется для каждого раздела. Сортировка и переключение List/Board остаются видимыми. Другие single-select поля фильтруются по варианту или пустому значению, текст — по вхождению, число и дата — по точному значению.

Редактор поддерживает Single select, Text, Number и Date, включая незаполненные поля и очистку существующих значений. Ноль отличается от пустого поля. Для дробных чисел в редакторе используется точка; отображение числа следует языку интерфейса. Названия полей и вариантов сохраняются как в GitHub. Создание определений полей, iteration/multi-select и редактирование связанных встроенных полей пока выполняются в GitHub. Доска продолжает группироваться по статусу.

Перед созданием задачи все переданные поля проверяются. Если задача создана, а сохранение полей не завершилось, интерфейс показывает частичный успех и ссылку, чтобы не создавать дубликат. Эти сценарии проверяются подменёнными запросами, без записи в рабочий проект.

## Выбор исполнителей

В существующей и новой задаче исполнители выбираются в раскрывающемся списке с поиском по имени или GitHub login; можно отметить несколько людей (до 10), снять выбор и завершить кнопкой Done. Поиск не добавляет произвольные логины. Для issue/PR список загружается из assignableUsers выбранного репозитория, для черновика — из известных участников проекта и текущего аккаунта. Текущие назначения сохраняются в списке даже без совпадений поиска; при ошибке lookup остаются доступными известные участники с предупреждением. Смена проекта или репозитория при создании очищает выбор исполнителей.

Изменение списка пока редактирует только форму: запись в GitHub происходит кнопкой Save/Create. Escape закрывает список, сохраняя открытую задачу. Неполный список назначенных участников блокирует редактирование, чтобы не удалить скрытые назначения.

## Вложения в комментарии

Выбор файла сразу загружает его в GitHub, ещё до публикации комментария. Поддерживаются PNG, JPG/JPEG, GIF, WebP, SVG, MP4, MOV и WebM — до 5 МиБ на файл. PDF, ZIP и другие документы этим способом не загружаются. Нужен доступ на запись в репозиторий; черновики Projects не поддерживают вложения в обсуждение.

Удаление вложения из черновика комментария убирает ссылку из текста, но не удаляет уже загруженный файл из GitHub. Плагин использует существующие учётные данные и тот же [протокол загрузки, что официальный GitHub CLI](https://github.com/cli/cli/blob/trunk/internal/attachments/client.go): `uploads.github.com/user-attachments/assets`. Обновлять установленный `gh` ради этой функции не требуется. Тесты загрузки используют подменённые запросы; реальная загрузка файлов ими не подтверждена.

## Кэш и ограничения

Сервер хранит прочитанные данные в SQLite плагина. Срок свежести — 2 минуты; фоновое обновление по умолчанию каждые 15 минут (`refreshMinutes`, 0 отключает). Кнопка обновления запрашивает свежие данные. При сбое сохранённые данные остаются доступны с предупреждением об устаревании или неполноте.

Вложенные коллекции API ограничены первыми 100 элементами там, где нет отдельной пагинации; при неполноте выводятся предупреждения. Комментарии имеют отдельную пагинацию. Отображение неполного списка исполнителей блокирует его редактирование, чтобы не удалить невидимых участников. Проектные данные и доступ зависят от GitHub API и прав общего аккаунта.

## CLI для чтения

```sh
bb github-projects status --json
bb github-projects list --json
bb github-projects refresh --json
bb github-projects projects OWNER --json
```

CLI читает данные и обновляет локальный кэш; команд внешней записи нет. Агентам нельзя менять GitHub без инструкции пользователя.

## Разработка

```sh
npm install --ignore-scripts
npm test
npm run typecheck
bb plugin build
bb plugin install .
bb plugin reload github-projects
```

bb предоставляет runtime SQLite; `--ignore-scripts` позволяет установить зависимости без сборки нативного `better-sqlite3`. Тестам, использующим нативный SQLite, нужна совместимая нативная сборка. Обычный `npm install` вне ограниченной среды также допустим. Сборка обновляет `dist/`; для активации изменений установленного плагина требуется reload.
